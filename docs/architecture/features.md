## Merge repeated infrastructure, preserve different meanings

- **One authored-content service:** the flight tracker's sky journal is a topic/view of the same authored journal, not a second journal backend. A physical book, whiteboard and app can reference registered content artifacts with their own presentation and limits.
- **One item ledger:** found, crafted, gifted and wish-supplied items share stable identity and provenance. Bag storage and `HomePlacement` describe where an item is; they are not competing inventories. Digital artifacts are referenced content, not another ownership database.
- **One creation pipeline:** self-builds, worker jobs and installed project outputs converge on validated artifacts/items and receipts. Preserve the weather study as existing progress and a migration fixture.
- **One wish ledger:** home, aircraft and tool requests share the real-week allowance. A wish requests something absent; a project uses available capabilities to undertake work. Keep both.
- **One interaction port:** residents, entities, objects and visitors use the same capability discovery/execution boundary while retaining different behavior and authority.
- **One capability lifecycle:** the external connector port and world interactions reuse future request/receipt infrastructure, while external account grants, recipient acceptance and operator approvals remain separate checks. Provider SDK/MCP tools never bypass host policy.
- **One attention pipeline:** notification delivery, attention and reaction remain separate across messages, external observations and world events.
- **One memory query port:** cue, lexical and vector indexes retrieve the same source episodes; indexes never become parallel truth stores.
- **One rest-time consolidation lifecycle:** dreams annotate the same source-linked memories and can suggest temporary waking impulses. Imagined scenes, revisable interpretations and verified events remain distinct. Missing-capability requests still use the one weekly wish ledger.
- **One character instruction source and action contract:** transports carry trusted character context and the same validated command vocabulary. They do not define Hubert's personality.
- **One spatial kernel and one rendering ownership model:** movement/sight semantics are shared across server/client consumers; each GPU resource has an explicit owner.

Do not merge these distinct records or scopes merely because their names overlap:

| Keep distinct                                                                | Why                                                                   |
| ---------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Visitor visit journal / automatic character activity log / authored notebook | Different authors, audiences, retention and purposes                  |
| World object / item instance / digital artifact / home placement             | Different identity, content and location responsibilities             |
| Wish / project / memory / journal entry                                      | Request, execution, experience and expression are separate lifecycles |
| Owner bearer / account world-admin role / creature home ownership            | Different permissions and trust boundaries                            |
| Living entity / autonomous resident / human visitor                          | Different control, needs, decision and authentication mechanisms      |
| Fictional resources / provider credits / wallet funds                        | Different accounting and authority; none implicitly grants the others |

## Operator resources

Cloudflare is the preferred production host for the world runtime, storage and ordinary inference. Vercel remains a secondary host for isolated previews and future resident apps; the tested Docker/PostgreSQL deployment remains portable. The [deployment guide](deployment.md#preferred-cloudflare-deployment) distinguishes that planned native adapter from the existing implementation. The public repo stays under the operator's personal GitHub account. [Ownership and hosted Hubert](ownership-and-hosting.md) describes separate platform/character authority, the sole-resident admission policy and the opt-in private inference deployment.

Personal credit allowances and grant details are preserved in the ignored operator resource notes, outside the public source release. Provider adapters do not assume grant eligibility or current balances. Resource attribution and real spending limits remain separate from the simulation's fictional needs and materials.
