Requires the local Ollama service and downloaded model. Use pnpm dev for the deterministic planner.

Add a connection

pnpm run setup

Choose model, Stripe or email. Secret entry is hidden; nothing is transmitted by setup.

Saved does not mean connected. The cloud model has an explicit launch command. Stripe and email are staged for adapters that are still being built. Setup grants no permissions and does not send mail, create webhooks or accept payments.

01 / A model connection

Explicit launch

Optional. Choose a trusted provider with a chat-completions-compatible endpoint. Use a dedicated project key and set a provider-side spending limit.

  1. Copy the provider’s base URL and model identifier from its documentation. Include /v1 when that provider requires it.
  2. Create an API key for this project. Keep the provider dashboard open while you configure its allowance.
  3. Run the command below. Paste the key into the hidden prompt and choose a daily request limit; the suggested starting point is 20.
pnpm run setup model

Start this model only when you want to use it:

pnpm dev:configured

Only Hubert is instantiated today. This launcher reads his model profile and delivers its key to the API process, not the Vite process. Saved connector keys remain unused. Existing .env settings still apply to ordinary launches; setup does not rewrite them.

The selected provider can receive Hubert’s context, including recent private visitor notes. A request-count limit is not a currency cap. Stopping the configured process ends this profile’s use; restart with pnpm dev:ollama for local inference.

02 / A little shop

Staged only

Prepare a dedicated Stripe sandbox. We do not need your live payment account key, bank details or customer data for development.

  1. Create or select a sandbox in the Stripe Dashboard. Confirm the selected environment before creating a key.
  2. Under API keys, create a restricted key named for Elsewhere/Hubert. Start with permissions set to None; the adapter’s endpoint list will determine the exact permissions when it is implemented. No broad key is necessary just to stage credentials.
  3. Run setup and paste the key beginning with rk_test_. Live keys and unrestricted sk_ keys are rejected.
pnpm run setup stripe

Skip the optional webhook secret for now. Once a real sandbox endpoint exists, its signing secret can be saved by running setup again. Replacing a profile asks for confirmation and requires entering its settings again.

Key format checks do not verify validity or permissions. The future adapter must verify the account/environment, grant only approved offers and reconcile signed payment events. Your operator/business remains the merchant. Live activation, fulfillment and public merchant details need a separate setup step.

03 / A return address

Staged only

Choose a dedicated sender such as hubert@your-domain.example. The domain and account belong to you; correspondence will use character-scoped permissions.

  1. Add and verify your sending domain in Resend, using the DNS records it gives you.
  2. Create an API key with Sending access restricted to that domain. Do not choose Full access.
  3. Run setup. Paste the re_ key privately and enter the sender’s plain email address.
pnpm run setup email

This prepares outgoing mail credentials only. Sending, verification emails for Better Auth, inbound mail, consent management and automatic replies are not connected by this command. No test mail is sent.

Source: Sending access and domain restrictions

04 / Keep these for later

No keys needed yet

These need an adapter and a concrete target first. Account names, preferred domains and repository names are useful planning information; access tokens can wait.

GitHub

A dedicated repository or organization. Later, install a GitHub App on selected repositories. We will need app/installation identifiers and protected signing credentials then. No personal access token now.

Private chat

Choose Telegram or another channel. A future Telegram adapter would use a dedicated bot created through BotFather and explicitly enrolled chats. Do not paste bot tokens into browser URLs.

Vercel / Cloudflare

Choose the operator accounts and isolated projects that should receive the deployment and credits. We will use project-specific access where supported, then install secrets into the host’s secret store. No administrator token or account password now.

Public presence

Choose a domain and Hubert’s public handle. Public posting begins with drafts and review; a social account does not give the character authority over your other accounts.

05 / A place for each key

Local location
.data/credentials/hubert/model.json
.data/credentials/hubert/stripe.json
.data/credentials/hubert/email.json
File protection
Owner-only plaintext: 700 directories, 600 files, ignored by Git. macOS/Linux only in this version. This is local development storage, not an encrypted vault.
Runtime access
Only the explicit configured launcher reads the model. No automatic discovery of staged connector secrets. Nothing enters the public world, frontend bundle or character memories.
Other characters
pnpm run setup stripe --character another-name saves a separate profile. It does not instantiate another resident or grant access.
Hosted delivery
Not implemented yet. Local paths are not deployment configuration; secrets must be installed separately for each chosen hosting environment.
pnpm run setup status

Status reports only saved/missing/unsafe. It never displays keys or claims a provider connection is verified. Existing .env, owner credentials and lived state are preserved.

If setup refuses a storage directory

It rejects symbolic links, shared permissions, files owned by someone else and linked credential files. For your own ordinary project .data directory, check permissions with ls -ld .data; if appropriate, make it private with chmod 700 .data. Do not change ownership or permissions of an unfamiliar path just to bypass a refusal.

If you need to rotate or remove a key

Rotate or revoke it in the provider dashboard, then rerun the matching setup command and explicitly replace the local record. Restart any configured model process to load the new key. Deleting a local file does not revoke a provider credential. Keep private files out of support uploads and shared backups.
